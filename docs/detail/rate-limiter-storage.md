# Реализация собственного хранилища счётчиков ограничителя частоты запросов

Встроенное `FileStorage` подходит для разработки и небольших проектов, но в продакшене часто требуется более
производительное или распределённое хранилище. Вы можете заменить его на собственную реализацию, сохранив совместимость
с `RateLimiterMiddleware`.

## Контракт StorageInterface

Все хранилища должны реализовывать интерфейс `Vasoft\Joke\Contract\Http\RateLimiter\StorageInterface`:

```php
interface StorageInterface
{
    /**
     * Инкрементирует счётчик для ключа и возвращает новое значение.
     *
     * Запись должна быть атомарной в рамках одного процесса.
     * Если ключ не существует, создаёт его со значением 1.
     * Всегда инкрементирует, даже если счётчик превышает лимит.
     *
     * @param non-empty-string $key Идентификатор клиента
     * @param int              $ttl Время жизни (секунды). По умолчанию 3600.
     *
     * @return int Новое значение счётчика
     */
    public function increment(string $key, int $ttl = 3600): int;
}
```

### Требования к реализации

**Атомарность.** Метод `increment()` должен гарантировать, что чтение текущего значения, инкремент и запись происходят
как единая неделимая операция. При конкурентном доступе из нескольких процессов (FPM, воркеры) два одновременных вызова
с одним ключом должны вернуть разные последовательные значения. Неатомарная реализация приведёт к неточному подсчёту и
возможным обходам лимита.

**TTL.** TTL перезапускается при каждом вызове `increment()` — это основа алгоритма Sliding Window. Реализация может 
использовать встроенные механизмы экспирации (Redis EXPIRE, Memcached TTL) или ручную проверку timestamps.

**Создание ключа.** Если ключ не существует, `increment()` должен создать его со значением `1`, а не бросать исключение
или возвращать `0`.

**Инкремент сверх лимита.** Метод всегда увеличивает счётчик, даже если он уже превышает лимит. Middleware
самостоятельно определяет факт блокировки по возвращаемому значению. Хранилище не должно знать о лимитах — оно только
считает.

**Безопасность типов.** Параметр `$key` всегда является непустой строкой (`non-empty-string`). Возвращаемое значение —
всегда положительное целое число.

## Регистрация в контейнере

Замените стандартную привязку в вашем [сервис-провайдере](./providers.md):

```php
use Vasoft\Joke\Contract\Http\RateLimiter\StorageInterface;
use App\RateLimiter\RedisStorage;

// В методе register() вашего ServiceProvider
$this->serviceContainer->registerSingleton(
    StorageInterface::class,
    RedisStorage::class,
);
```

После этого `RateLimiterMiddleware` автоматически получит вашу реализацию через внедрение зависимостей. Никаких
изменений в маршрутах или конфигурации не требуется.

## Пример: InMemoryStorage

Ниже приведён пример простейшего хранилища для тестирования и одноразовых скриптов. **Не используйте его в продакшене
** — данные теряются между запросами и не разделяются между процессами.

```php
<?php

declare(strict_types=1);

namespace App\RateLimiter;

use Vasoft\Joke\Contract\Http\RateLimiter\StorageInterface;

final class InMemoryStorage implements StorageInterface
{
    /** @var array<string, array{value: int, expiresAt: int}> */
    private array $data = [];

    public function increment(string $key, int $ttl = 3600): int
    {
        $now = time();

        // Удаление устаревшей записи
        if (isset($this->data[$key]) && $this->data[$key]['expiresAt'] <= $now) {
            unset($this->data[$key]);
        }

        // Инкремент или создание
        $current = $this->data[$key]['value'] ?? 0;
        $newValue = $current + 1;

        $this->data[$key] = [
            'value' => $newValue,
            'expiresAt' => $now + $ttl,
        ];

        return $newValue;
    }
}
```

Обратите внимание на структуру: каждая запись хранит и значение, и метку времени экспирации. Это необходимо, потому что
TTL перезапускается при каждом инкременте.

## Рекомендации для продакшн-реализаций

**Redis.** Используйте команду `INCR` + `EXPIRE` внутри Lua-скрипта или транзакции для гарантии атомарности. Одиночные
команды `INCR` и `EXPIRE` без группировки не являются атомарными и могут привести к утечке ключей без TTL при сбое между
командами.

**Memcached.** Используйте операцию `increment` с флагом создания ключа. Memcached поддерживает атомарный инкремент
нативно, но обратите внимание: при отсутствии ключа поведение зависит от версии и флагов.

**База данных.** Используйте `INSERT ... ON CONFLICT UPDATE` (PostgreSQL) или `INSERT ... ON DUPLICATE KEY UPDATE` (
MySQL) с колонкой `updated_at` для управления TTL. Обязательно добавьте индекс по ключу и настройте периодическую
очистку устаревших записей.

**Файловая система.** Если вы пишете улучшенное файловое хранилище, используйте файловые блокировки (`flock`) для
обеспечения атомарности. Встроенный `FileStorage` уже делает это через `FileCache::modify()` — изучите его реализацию
как отправную точку.
